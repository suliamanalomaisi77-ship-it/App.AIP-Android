# مشروع تطبيق AIP لنظام Android

**AIP – العميسي للإنتاج المبكر**

هذا مشروع Flutter أصلي لتطبيق Android، وليس موقعاً إلكترونياً. يحتوي على واجهة عربية RTL، هوية داكنة بالأزرق والسماوي، قائمة خدمات مع شرح تفصيلي، صفحات تفاصيل الخدمات، نموذج طلب، تبويب طلباتي، وتسجيل حساب بالبريد الإلكتروني عبر Supabase عند ربط المشروع.

## الخدمات المدرجة

- التصميم والإعلانات: إعلانات المحلات والشركات، المنتجات والعروض، الشعارات، الهويات البصرية، بطاقات الأعمال والمنشورات.
- التصاميم الدينية: جمعة مباركة، الآيات، الأذكار والأدعية، خلفيات واتساب، المناسبات الإسلامية.
- المناسبات: الزواج والخطوبة والتخرج وعيد المعلم والتهاني والتكريم والمناسبات الخاصة.
- الفيديو والمونتاج: فيديوهات إعلانية، مونتاج، مؤثرات، إضافة الصوت إلى الصور، كتابة كلمات الصوت، فيديوهات الشركات والمنتجات.
- الأغاني والشيلات: شيلات حسب الاسم، تهاني صوتية، اسم المهدي إليه، ومقدمة من شخص إلى شخص.
- الذكاء الاصطناعي: صور إبداعية من الوصف، صور شخصية، تحسين الدقة، تعديل الصور.
- العروض التقديمية: عروض الشركات والمشاريع والتعليم والجامعة وPowerPoint.

## المتطلبات

- Flutter SDK حديث (3.24 أو أحدث موصى به).
- Android Studio وAndroid SDK.
- مشروع Supabase فعلي لتشغيل الحسابات والطلبات.
- Firebase project لتفعيل Push Notifications لاحقاً.

## تشغيل المشروع

1. ثبّت Flutter وAndroid Studio.
2. افتح مجلد المشروع في Android Studio أو VS Code.
3. نفّذ `flutter pub get`.
4. أنشئ مشروعاً في Supabase.
5. نفّذ محتوى `supabase/schema.sql` في SQL Editor.
6. أنشئ Storage bucket خاصاً باسم `aip-private`، وأضف سياسات التخزين الآمنة قبل تفعيل رفع الملفات.
7. شغّل التطبيق أثناء التطوير بالأمر:

```bash
flutter run --dart-define=SUPABASE_URL=YOUR_SUPABASE_URL --dart-define=SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

8. لبناء APK تجريبي:

```bash
flutter build apk --release --dart-define=SUPABASE_URL=YOUR_SUPABASE_URL --dart-define=SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

المخرج المتوقع: `build/app/outputs/flutter-apk/app-release.apk`.

## إعداد المدير

لا تضع كلمة مرور المدير داخل التطبيق أو داخل هذا المستودع. أنشئ مستخدم المدير من Supabase Authentication، ثم بعد التحقق من هويته غيّر `role` إلى `admin` في جدول `profiles` من لوحة Supabase. يجب أن تتم هذه الخطوة من حساب مالك المشروع فقط. لا تمنح العميل صلاحية تعديل `role`.

ملاحظة: هذا الإصدار الأولي يوفّر أساس التطبيق وربط الحسابات والطلبات وقيود RLS. **لوحة الإدارة المستقلة، رفع الملفات الفعلي، إدارة المعرض والعروض، الإشعارات الفورية، النسخ الاحتياطي، وتكامل رقم الهاتف OTP تحتاج استكمال وربط إعدادات المشاريع السحابية واختبارها قبل اعتبار المنتج جاهزاً للنشر.** لا توجد بيانات اعتماد سحابية أو مفاتيح توقيع APK مضمّنة.

## النشر في Google Play

يلزم حساب Google Play Console باسم المالك/الجهة، إعداد سياسة الخصوصية وبيانات أمان البيانات، أيقونة ولقطات شاشة، ثم بناء ملف AAB موقّع بمفتاح إصدار محفوظ بأمان. لا ترفع APK debug إلى المتجر. راجع متطلبات Google Play الحالية قبل الإرسال.
